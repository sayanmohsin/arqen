# Phase 01: Documentation and Contracts\n\n## Objective\n\nDefine the stable Arqen contracts before framework implementation.\n\n## User-visible outcome\n\nA future implementer can build the CLI, runtime, thingd adapters, tools, jobs, and deployment path without making foundational API decisions.\n\n## Dependencies\n\nNone. This phase is currently **planned**.\n\n## In scope\n\nRepository/crate boundaries; configuration; memory and HTTP thingd modes; startup output; health/readiness; logging/redaction; CLI behavior; tool metadata; job lifecycle; agent manifest; Docker/deployment expectations.\n\n## Out of scope\n\nRust implementation, CLI implementation, generated templates, cloud integration, and changes to sibling repositories.\n\n## Required repository state\n\nCurrent Arqen repository is documentation-only and existing docs are available under docs/.\n\n## Deliverables\n\nContract documents, examples, decision records, and updates to docs/roadmap.md.\n\n## Acceptance criteria\n\nSee `acceptance.md`; all items must pass before completion.\n\n## Test requirements\n\nSee `test-plan.md`; record commands and outcomes in `handoff.md`.\n\n## Documentation requirements\n\nUpdate README, architecture, commands, logging, thingd, typed-tools, durable-jobs, Docker, deployment, and roadmap docs.\n\n## Handoff procedure\n\nComplete `handoff.md`, update `STATUS.md`, list changed files, record limitations, and identify the next phase.\n
