# Phase 07: Optional Cloud Adapter\n\n## Objective\n\nAdd optional hosted thingd-cloud integration without coupling Arqen to private cloud internals.\n\n## User-visible outcome\n\nAn Arqen app can use a documented cloud customer API through the same repository, auth, and job interfaces as direct thingd.\n\n## Dependencies\n\nPhases 03, 04, 05, and a public cloud contract. This phase is currently **blocked**.\n\n## In scope\n\nJWKS identity verification, tenant resolution, instance discovery, cloud repository/job adapters, compatibility tests, feature-gated package.\n\n## Out of scope\n\nCloud control-plane implementation, private modules, direct database access, billing, provisioning implementation, and undocumented endpoints.\n\n## Required repository state\n\nA versioned public cloud customer API exists and direct thingd adapter passes its tests.\n\n## Deliverables\n\n`arqen-cloud` feature/crate, configuration docs, contract fixtures, compatibility suite, and security notes.\n\n## Acceptance criteria\n\nSee `acceptance.md`; all items must pass before completion.\n\n## Test requirements\n\nSee `test-plan.md`; record commands and outcomes in `handoff.md`.\n\n## Documentation requirements\n\nUpdate deployment, thingd integration, and cloud adapter docs with the exact supported public contract.\n\n## Handoff procedure\n\nComplete `handoff.md`, update `STATUS.md`, list changed files, record limitations, and identify the next phase.\n
